# Release parity: NanoDictate

This is a read-only parity report between the restored Continuum release control
plane and the working NanoDictate pipeline. NanoDictate was not modified, its
release writers were not switched, and no NanoDictate release was created while
producing this report.

## Evidence read

- `kodmial/nanodictate/.github/workflows/release.yml` and
  `nanodictate-release-engine.yml` (release trigger, version gate, build/sign,
  Windows package, GitHub Release, Scoop, manifests);
- `release-pr.yml` and `nanodictate-release-pr-engine.yml` (release-please
  proposal, skip-release label, changelog cut);
- `release-automation-merge.yml` and
  `nanodictate-release-automation-merge-engine.yml` (trusted merger);
- `release-notes.yml`, `packaging-smoke.yml`, `windows-release-smoke.yml`;
- the latest published release (`v0.1.46`) asset list.

## Remaining NanoDictate cutover seams

A distinct future cutover task must resolve these before switching the production
writer. This issue deliberately does not do so.

1. **Release PR integration.** Decide whether release-please stays the proposer
   and Continuum consumes its branch/manifest through `release_pr`, or whether
   the generic release-PR hook replaces it. The CLI needs a proposal/manifest
   input before either can be wired without a custom script.
2. **Tested-candidate reuse.** Nano publishes bytes already validated by
   Packaging smoke and CI. The generic workflow rebuilds from the same SHA. A
   cutover must either accept a rebuild with equivalent verification or add an
   explicit "reuse this candidate run/artifact" phase.
3. **Apple signing entry point.** `apple.py` is tested and preserves the stable
   identity contract, but the reusable workflow drives `hooks.py`. A cutover must
   either translate the Nano codesign/bundle steps into a hooks document or add a
   first-class Apple config-target execution path.
4. **Union checksum asset.** Generate Nano's single `SHA256SUMS.txt` from the
   complete published asset set, either as a publisher hook or as a new built-in
   destination behavior.
5. **Windows setup.exe.** Keep the NSIS/installer generation in the consumer's
   Windows build command; Continuum only requires the declared output.
6. **Homebrew and MacPorts writers.** Move formula/cask/Portfile regeneration,
   tap/tree pushes, and the `PIN_REV` verification into publisher/sync hooks, or
   keep Nano's existing manifest workflow as a downstream writer.
7. **One active writer and rollback.** Before cutover, disable the Nano release
   engine's publication path, keep its workflow installable for rollback, and
   document which repository variable or workflow switch owns the writer.

Until those are resolved, the NanoDictate release pipeline remains the source of
truth for NanoDictate and is untouched by Continuum.
